# Coding Constraints & Best Practices

## Styling Rules

- **NO `:hover` pseudo-class styling** - Do not use CSS `:hover` selectors anywhere in the application
- Use alternative interaction patterns (click handlers, state-based classes) instead of hover effects
- **Use Lucide icons exclusively** - All icons must come from lucide-icons library
- **Follow existing patterns** - Before creating any new styles, examine what has already been implemented and maintain consistency
- **Use variable-defined colors first** - Always prefer CSS variables/custom properties for colors unless explicitly asked to use specific values

## Component Architecture

- **Maximize reusable components** - Always look for opportunities to extract common UI patterns into reusable Vue components
- Prefer composition over duplication
- When you see similar code patterns appearing 2+ times, create a component

## State Management & Data Handling

- **Use computed properties** instead of creating multiple arrays or duplicating data transformations
- Keep data sources single and derive views through computed properties
- Example: Instead of maintaining separate filtered/sorted arrays, use one source array + computed properties

## Code Simplicity Principles

- Favor simplicity over cleverness
- Reduce complexity by using Vue's reactivity system (computed, refs) effectively
- Avoid unnecessary intermediate variables when computed properties can handle transformations
- Think "reactive first" - let Vue handle updates automatically

## General Guidelines

- Read existing code patterns before implementing new features
- Follow the established project structure and conventions
- When in doubt, ask clarifying questions rather than making assumptions
